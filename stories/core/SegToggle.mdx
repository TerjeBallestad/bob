## When to use

- To switch how the same data shows: day, week, month; list or board.

## When not to use

- For more than four options, or options with long names. Use [Select](?path=/docs/forms-select--docs).
- For an action. Use [Button](?path=/docs/core-button--docs).
- For a setting that is saved, on or off. A toggle switch reads better (Bob has none yet).

<DoDont>
<Do>

- Keep labels to one short word each.
- Keep the value in the parent and set it in `onChange`.

</Do>
<Dont>

- Leave `value` unset. Then no segment is active, and the control says nothing.

</Dont>
</DoDont>

## Usage

SegToggle keeps no state. The parent owns the value:

```tsx
const [range, setRange] = useState('week');
<SegToggle options={['day', 'week', 'month']} value={range} onChange={setRange} />
```

An option is a string, or `{ value, label }` when the label differs from the value.

## Accessibility

SegToggle is built on Base UI's ToggleGroup. Each segment is a native `<button>`, and the group has
one Tab stop.

<Keys rows={[
  ['Tab', 'Moves into the group, to the segment that last had focus (the first one at the start), and then out of the group.'],
  ['Arrow Right Arrow Left', 'Moves focus to the next or the previous segment, and wraps at the ends. Focus moves, the value does not.'],
  ['Home End', 'Moves focus to the first or the last segment.'],
  ['Enter Space', 'Makes the focused segment active: calls onChange.'],
]} />

- The group has `role="group"`. Each segment has `aria-pressed`: a screen reader tells which one
  is on.
- The focus ring is drawn inside the segment, because the group clips.
