# Button

<Lede>Starts an action on the current screen: save, archive, open a dialog.</Lede>

Button also takes every attribute of `<button>`: `onClick`, `type`, `aria-label`, `form`. Every
Button is `type="button"` unless you set `type`, so it never submits a form by accident. The
button that submits a form says `type="submit"`.

## When to use

- For an action that changes something here: save a form, archive a ticket, open a modal.
- In a modal footer, a toolbar, or at the end of a form.

## When not to use

- To go to another page. Use a link (`<a>`): it opens in a new tab and shows its address.
- For a choice between views or ranges. Use [SegToggle](?path=/docs/core-segtoggle--docs).
- For an entry in the sidebar. Use [NavRow](?path=/docs/board-navrow--docs).

<DoDont>
<Do>

- Use one `primary` button per view, for the action most people take.
- Write the label as a verb: **Save**, **Archive**, **Add task**.
- Put Cancel first and the main action last.

</Do>
<Dont>

- Put two `primary` buttons side by side. Make the second `secondary` or `ghost`.
- Use `danger` for an action that can be undone. It is for data that is gone after the click.
- Write **OK** or **Yes**. Say what happens.

</Dont>
</DoDont>

## Variants

<Canvas of={Stories.Variants} />

| Variant | Use it for |
| --- | --- |
| `primary` | The main action of a view. One per view. |
| `secondary` | Other actions of the same weight, beside a primary. |
| `ghost` | Quiet actions: Cancel, toolbar actions, actions in a row. |
| `accent` | An action that starts something new, in the indigo accent. |
| `danger` | An action that destroys data: Delete, Archive for good. |
| `danger-ghost` | The first step to a destructive action, which then asks in a modal. |
| `danger-tint` | A quiet destructive action inside a row, such as a running timer's stop. |
| `text` | An action that reads as text: "stop" in a top bar, "sign out", a row's delete `×`. |

`sm` is for toolbars, rows and dense forms. `md` is the default. `xs` is as small as a mono chip
(10.5px, 1px by 6px around the label, the Kbd radius), for a button inside a dense row:

```tsx
<Button variant="danger-tint" size="xs" className="font-mono">stop</Button>
```

## Text

<Canvas of={Stories.Text} />

`variant="text"` renders `btn btn-text`: no border, no fill, no padding, and no size class, so
`size` has no effect. It takes the font and colour of its parent, or of the classes you give it:

```tsx
<Button variant="text" className="text-caption text-muted hover:text-primary">sign out</Button>
<Button variant="text" aria-label="Delete entry" className="text-base text-faint hover:text-danger">×</Button>
```

- It has no hover style of its own. Give it one with a class, as above.
- It keeps Bob's focus ring and the disabled style of every Button (half opacity, no pointer).

## Override with Tailwind

In a Tailwind app, utilities in `className` win over Bob's classes, because both come out of the
same build (DD-031):

```tsx
<Button className="px-8 w-full">Save</Button>
```

## Accessibility

Button is a native `<button>`, so the browser gives it its role, focus and keys.

<Keys rows={[
  ['Tab', 'Moves focus to the button. A disabled button is skipped.'],
  ['Enter Space', 'Runs the action.'],
]} />

- **Name.** The label is the accessible name. A button with only a symbol (`×`, `⋯`) needs an
  `aria-label` that says the action: `aria-label="Close"`.
- **Disabled.** `disabled` removes the button from the tab order, and a screen reader user may not
  find it. When the reason matters, keep the button enabled and say what is missing after the click.
- **Focus.** The focus ring shows on keyboard focus only (`:focus-visible`).
