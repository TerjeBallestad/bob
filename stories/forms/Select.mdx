## When to use

- For one choice from five or more options, or from options with long names: a stage, an assignee.

## When not to use

- For two to four short options that switch a view. Use [SegToggle](?path=/docs/core-segtoggle--docs): all options stay in sight.
- For a search over many records. A select with a hundred options is hard to use.

<DoDont>
<Do>

- Order the options in a way the user can predict: by flow (inbox, planned, done) or A to Z.
- Pass `items` to Select, so the trigger shows the label and not the stored value.

</Do>
<Dont>

- Use an empty first item as the label. Put the label in a [FormRow](?path=/docs/forms-formrow--docs), and use `placeholder` on SelectValue for "no choice yet".

</Dont>
</DoDont>

## Usage

Select holds the state. The parts lay it out: the trigger with its value, and the list with its
items. The API is Base UI's.

```tsx
const stages = [
  { value: 'inbox', label: 'Inbox' },
  { value: 'planned', label: 'Planned' },
  { value: 'done', label: 'Done' },
];

<FormRow label="Stage">
  <Select items={stages} value={stage} onValueChange={(v) => v !== null && setStage(v)}>
    <SelectTrigger>
      <SelectValue />
    </SelectTrigger>
    <SelectContent>
      {stages.map((s) => (
        <SelectItem key={s.value} value={s.value}>{s.label}</SelectItem>
      ))}
    </SelectContent>
  </Select>
</FormRow>
```

- `value` and `onValueChange(value)` when the parent keeps the state; `defaultValue` when Select keeps it.
- `onValueChange` gets the item's value, not an event. Its type includes `null`, for a select with no value.
- `name` puts the value in a hidden input, so a `<form>` submits it. `required` and `disabled` work as on a native field.
- `className` on SelectTrigger sets its width: `<SelectTrigger className="w-40">`. Bob's class comes first, so a utility wins.

## The open list

The list opens over the trigger, with the chosen item on the trigger's value, as a native list
does on macOS.

## Groups and placeholder

SelectGroup and SelectLabel put a heading over some items, and SelectSeparator draws a line. A
disabled item shows, but takes no focus. `alignItemWithTrigger={false}` on SelectContent opens the
list below the trigger.

## Accessibility

Base UI gives Select the keys of a listbox. visual/keyboard.visual.ts tests each of them.

<Keys rows={[
  ['Tab', 'Moves focus to the trigger. Select is one Tab stop.'],
  ['Enter Space ↓', 'Opens the list, with focus on the chosen item.'],
  ['↑ ↓ Home End', 'Move through the items, in the open list.'],
  ['A–Z', 'Moves to the next item that starts with the letters typed.'],
  ['Enter', 'Chooses the item and closes the list.'],
  ['Escape Tab', 'Close the list with no change. Focus goes back to the trigger.'],
]} />

- The trigger is a `combobox`. Name it with a [FormRow](?path=/docs/forms-formrow--docs) label, or an `aria-label` on SelectTrigger. A click on the FormRow label opens the list, since the label clicks its button (a native select only took focus).
- An error is `aria-invalid="true"` on SelectTrigger, as on Input: a `danger` border, and a screen reader hears it. Point `aria-describedby` at the error text.
- The focus ring shows on the trigger, and a highlight on the item in the list.
- The list is in a portal at the end of `<body>`. A test that looks for an item must search the whole page.
