## Two forms

- **A field** (no `kbd`): the user types here, and the app filters as they type.
- **A button** (`kbd` set): it shows the placeholder and the key hint, and its `onClick` opens a
  command palette or a search dialog. Bob does not bind the key: the app listens for `/` or `⌘K`
  and opens the same thing.

<Canvas of={Stories.Live} />

The second field above has `expandOnFocus`: it widens from 150 to 210px while it has focus, for a
topbar where space is tight.

## When to use

- To filter the list on the screen, or to open search from a topbar.

## When not to use

- For a form field that is not a search. Use [Input](?path=/docs/forms-input--docs).

<DoDont>
<Do>

- Show the key hint only when the app binds that key.
- Filter as the user types; a search field needs no submit button.

</Do>
<Dont>

- Use the button form inside a form. It is a `<button>` and submits the form unless you set `type="button"`.

</Dont>
</DoDont>

<Controls of={Stories.Default} />

## Accessibility

<Keys rows={[
  ['Tab', 'Moves focus to the field or the button.'],
  ['Esc', 'Clears the field (the browser does this for type="search").'],
  ['Enter Space', 'With kbd: opens search, as a click does.'],
]} />

- The field needs an `aria-label`, such as "Search tickets", when no visible label names it.
- The button's name is its placeholder and its hint, for example "Search /". Pass an `aria-label`
  if that reads badly.

- Focus and error as Input: the focus ring, and a `danger` border with `aria-invalid="true"`.
