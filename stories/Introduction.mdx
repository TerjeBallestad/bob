## Who uses it

- **pm-board**, the dashboard of the pm boards, through the Tailwind entry.
- **Time Turtle**, through the JS import. It moves to Tailwind next.

Both apps pin an exact version. A release reaches an app when the app bumps it.

## Install

```sh
npm i @terjeballestad/bob
```

`react` and `react-dom` 18.3 or later, and `@types/react`, are peer dependencies.

### In a Tailwind v4 app

Add one line after your Tailwind import:

```css
@import "tailwindcss";
@import "@terjeballestad/bob/tailwind.css";
```

Your Tailwind build then writes Bob's component classes (`btn`, `chip`, `ticket-card`, …) next to
your utilities, and only the ones in use. They take variants (`md:btn-sm`), and your utilities win
over them: `<Button className="px-8">` gets 32px of side padding.

```tsx
import { Button } from '@terjeballestad/bob';

<Button variant="primary" onClick={save}>Save</Button>

// The same look, without React:
<button className="btn btn-md btn-primary">Save</button>
```

The import from `@terjeballestad/bob` also loads Bob's precompiled stylesheet, which brings the
webfonts (Schibsted Grotesk and JetBrains Mono). It sits in the `base` layer, so your build's
classes win over it.

### In an app without Tailwind

Import the components. The import loads `bob.css` with the tokens, the fonts and every class:

```tsx
import { Button, Chip } from '@terjeballestad/bob';
```

If your bundler drops CSS that a package imports, add `import '@terjeballestad/bob/styles.css'`
once at the root of the app.

### Two rules for your own CSS

- **Element rules go in `@layer base`.** Bob's classes sit in a cascade layer. An unlayered rule
  such as `button { color: inherit }` beats every layered class, Bob's too:

  ```css
  @layer base {
    button { font: inherit; color: inherit; }
  }
  ```

- **Preflight changes the look.** Bob assumes its own reset, not Tailwind's preflight. With
  preflight, text sits at line-height 1.5 and Bob's rows grow. An app written without preflight
  imports Tailwind's theme and utilities only, as pm-board does:

  ```css
  @layer theme, base, components, utilities;
  @import "tailwindcss/theme.css" layer(theme);
  @import "tailwindcss/utilities.css" layer(utilities);
  @import "@terjeballestad/bob/tailwind.css";
  ```

## Tokens: scales, then roles

Every value is a CSS custom property on `:root`. Colour has two layers:

- A **scale** holds the values: `--gray-1` to `--gray-26`, and indigo, blue, green, orange,
  purple, yellow, red and gold, numbered on the 12 steps of Radix Colors. Only scale steps hold colour literals; a test fails on
  any other.
- A **role** says what a colour is for and points at a step: `--surface-card` is `--gray-8`,
  `--text-2` is `--gray-24`. Components use roles, never steps.

In Tailwind, the theme maps the tokens: `bg-surface-card`, `rounded-btn`, `font-mono`. A later
major version renames the roles to read as classes (`bg-card`, `text-secondary`,
`border-subtle`, DD-033). These pages use today's names.

[Tokens](?path=/docs/tokens--tokens) shows every scale, each role with its step, and the WCAG
contrast of each text role on each surface.

## Conventions

- **Overrides.** Components that wrap a native element (Button, Chip, Input, Select, Textarea,
  SearchInput) take `className` and every attribute of that element. The others take `style`.
- **No state.** Bob's components keep no state. The app owns `open`, `value` and the list of
  toasts.
- **No icons.** Bob shows state with dots, mono chips and a few unicode characters.
- **Tests.** Every story has a screenshot test with no pixel tolerance. Modal, Select, SegToggle
  and Toast also have interaction tests: the stories marked *(test)*, which CI plays in the built
  Storybook.
